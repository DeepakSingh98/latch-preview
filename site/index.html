A compiler for training megakernels

If you want to test a new way for models to learn, you shouldn’t have to become a kernel engineer first.

Well-funded labs such as Flapping Airplanes have built their own megakernel frameworks to explore data-efficient learning. For researchers outside those labs, the systems work remains a serious barrier.

Latch is a first step toward an open-source alternative. Write a supported model, loss and update rule in PyTorch, and get one generated GPU program for the forward pass, backward pass and optimizer.

Latch is a research preview for NVIDIA H100 GPUs. It supports a limited set of models and learning rules today. Our goal is a general compiler for training megakernels.

Why megakernels

GPUs are fast at large matrix products. Some learning algorithms need many small computations that depend on one another. Running them as separate kernels adds launch overhead and requires intermediate results to pass through GPU memory.

Latch combines those operations into one program. We started with two kinds of work:

  • Fine-grained experts. Each token uses a few small networks. Routing tokens, running the experts and collecting their gradients creates many small, uneven operations.
  • Test-time learning. A model updates its memory or weights as it reads. These frequent, dependent updates are a natural fit for a persistent GPU program.

From TinyMoE to a training megakernel

We used Latch to automatically generate a complete training megakernel for the public TinyMoE-200M language model. The compiler turns the model and its training rule into one GPU program. It performs the forward pass, loss, backward pass, gradient clipping and AdamW update.

Generation and compilation take about five minutes on a 64-vCPU machine. How compilation works.

Both implementations learned at nearly the same rate per token. Latch reduced update time from about 140 ms to 80 ms. The model therefore reached the same quality sooner.

Test-time learning

GradLev adapts GPT-2 small’s final feed-forward layer as it reads a passage. It uses each token’s prediction error to update that layer before predicting the next token.

Latch runs all 1,024 predict-and-update steps in one generated kernel. The changing weights stay in on-chip memory. Compiled PyTorch uses 18,176 kernels for the same loop and replays them through a CUDA graph. Both implementations use ordinary PyTorch for the rest of GPT-2.
